# PromoLens · 促销门店对照分析

把一个促销活动的**曝光、订单、退款和门店分组**接到一起，回答一个看起来简单、实际很容易答错的问题：

> 促销门店在活动期的每会员净销售变化，比对照门店高多少？

门店分组不是随机分配的，退款又会晚到，所以页面不会把两组的相关性直接写成“提升”。它同时给出：

* **原始差异**：不调整门店构成的两组差；
* **调整后估计**：在明确写出的假设下，用倾向得分匹配或精确分层得到的可比差异；
* 被排除的样本、共同支持范围、平衡性（SMD）与敏感性分析；
* 每份报告绑定的**完整输入**（冻结快照、规则/观察窗/方法版本、参数、筛选、引擎版本）与可导出的依据。

页面是真实的 Web 应用：Python 标准库 HTTP 服务 + 原生 JS/SVG 单页界面，无第三方运行时依赖。

## 快速开始

```bash
./run.sh            # 首次运行自动生成合成数据（约 30–60 秒），然后打开 http://127.0.0.1:8080
./run.sh --reset    # 重新生成演示数据与数据库
```

也可以分步运行：

```bash
python3 -m promolens seed --db var/promolens.db --data-dir var/data [--reset] [--order-scale 1.0]
python3 -m promolens serve --db var/promolens.db --data-dir var/data --port 8080
```

要求：Python 3.11+，不需要 pip 安装任何包。数据与数据库都在 `var/`（已被 `.gitignore` 忽略）。

测试：

```bash
python3 -m unittest discover -s tests -t . -v
```

## 合成数据里刻意放进来的两件事

数据由 `promolens/seed.py` 确定性生成（随机种子固定），不包含任何真实业务信息：

| 设计 | 表现 |
| --- | --- |
| **选择偏差** | 促销门店更可能是大店、高客流、高城市化、高会员占比；同一批特征也抬高每会员消费，并且与活动期的自然增长相关。 |
| **迟到退款** | 促销组退款率更高；约 35% 的退款发生在分析截止日之后，分成 `refunds_initial.csv` 与 `refunds_backfill.csv` 两批到达。 |
| **脏数据** | 3 行非法数据（净额不等于毛额减折扣、未知渠道、非法时间）会被逐行隔离，不进入分析。 |

因此：原始差异明显偏大；匹配/分层后估计会缩小，但不会变成 0；改用“包含已到账退款”的口径会继续下调促销组净销售。这些是数据设计的结果，不是商业结论。

`var/data/truth.json` 记录生成参数供测试核对，页面不展示它。

## 页面怎么用

### 分析页

左侧选方法，改条件，点“重算并新建版本”。每个条件组合是一个**组合（combo）**，每次重算生成该组合的下一个**版本**。

* **方法**（用样本量交换可比性）
  * `原始两组对照`：全部合格门店、门店等权。不调整构成，差异同时包含选择偏差。
  * `倾向得分匹配`：ridge 逻辑回归估计倾向得分，卡钳内 1:1 最近邻（默认不放回），只比较共同支持区间内的门店；卡钳越小越可比、丢样本越多。
  * `精确分层对照`：区域×业态精确分层，只用两组都存在的层，层内按会员数加权；单臂层整体排除。
* **退款处理**：`只计退款截止日前到账` / `使用快照内全部已到账退款`。后者只有在回补后才有区别。
* **观察窗**、**订单门槛**、区域/业态筛选、手动排除门店。
* **曝光归属规则**：回看窗口、可归因订单状态、渠道、曝光类型、同店/订单前约束。改动会创建新的规则版本。
* 结果区分页：总览 / 可比性与支持 / 门店明细 / 排除样本 / 曝光归因 / 敏感性 / 依据与版本。
* 点门店行打开抽屉：周度净销售图、窗口汇总、当前方法权重、匹配对象、加入排除列表。
* 每份完成的报告可导出：依据 JSON（含复现请求体）、门店 CSV、方法 Markdown。

### 版本对比页

选两版已完成报告，列出**哪些输入不同**（快照、规则值、观察窗、方法版本/参数、口径、筛选、门槛）和指标差值、样本覆盖、调整后最大 |SMD|。输入相同应得到相同结果；如果不同，说明存在未被冻结的输入，属于缺陷。

### 数据与口径页

接入批次（新增/更新/未变/拒绝）、被拒绝的原始行、当前快照、规则/观察窗/方法版本、报告队列状态；可一键执行**退款回补**（写入落地表 + 冻结新快照，不改写任何已有报告）。

## 一致性设计：报告为什么不会被旧结果覆盖

这是应用的核心约束，实现在 `promolens/db.py`、`ingest.py`、`versions.py`、`reports.py`：

1. **内容寻址的不可变快照**。`create_snapshot()` 用落地表全部行的行哈希计算 `snapshot_hash`，并把数据复制进 `snapshot_*` 表。内容相同则复用同一哈希；任何后续接入都不会改动旧快照。快照哈希只由内容决定（不含批次号/时间），因此重新接入同一份文件不会制造“假新快照”。
2. **版本化定义只增不改**。新规则/观察窗版本会把旧版本标记为 `retired`，但绝不修改旧版本的字段。报告入库时把**解析后的完整取值**写进 `spec`，执行时也按 `spec` 里的版本号重新读取，而不读“当前启用版本”。
3. **报告冻结输入摘要**。`inputs_digest = H(引擎版本, 快照哈希, 规则值, 观察窗值, 方法版本与参数, 筛选, 门槛)`；`payload_digest` 覆盖所有结果字段。复现请求体原样保存，重放得到同一个摘要。
4. **条件式收尾**。worker 认领任务时把报告从 `queued` 原子改为 `computing`；最终写结果时再次检查 `status='computing'`，否则把这次运行标为 `discarded`。同组合出现新版本时，旧任务被 `superseded`，即使跑完也不能写入。
5. **分析只读快照**。`analysis.analyze()` 从 `snapshot_*` 读取，从不读落地表，所以并发接入/回补不会影响正在运行的任务。
6. **持久化事件链**。`report_events` 记录入队、开始、完成、失败、被取代；`analysis_runs` 记录每次尝试与错误。

SQLite 使用 WAL 与 `BEGIN IMMEDIATE`，并发写入串行化，报告读取不受阻塞。

## 方法与统计边界（页面同样展示）

* 估计量：门店层面的 `活动期每会员净销售率 − 期前每会员净销售率`（按 28 天折算），组间再作差。这是 DiD 形式的关联差异，不是随机化效应。
* 匹配假设：已观测门店特征足以解释分组与结果的共同原因（条件可忽略性），且重叠区间内存在可比对照。未观测混杂无法被这些协变量检验。
* 分层假设：层内分组近似随机，层间效应可按会员数加权平均。
* 置信区间：门店/匹配对/层层面重抽样的百分位区间（600 次，随机数种子由输入摘要决定，因此可复现），**不构成随机化推断**。
* 敏感性分析：切换退款口径、1.5×IQR 剔除离群结果、不同卡钳宽度、每层至少 2 家、按会员数加权。它是“换一个选择结果会怎样”，不是误差范围。
* 归因：订单向前回看窗口内最近一次合格曝光；同刻多条曝光按 `exposure_id` 决胜。归因占比描述的是口径覆盖，不是增量。

## 目录

```
promolens/
  db.py          SQLite 模式（落地表、快照表、版本表、报告/运行/事件）与哈希工具
  ingest.py      CSV 校验、幂等 upsert、拒绝行隔离、内容寻址快照
  versions.py    规则/观察窗/方法版本，校验与种子
  analysis.py    归因、指标、raw/matched/stratified、bootstrap、平衡、敏感性、下钻
  reports.py     组合/版本、入队、worker、条件收尾、对比、陈旧检测
  server.py      JSON API + 静态文件服务
  seed.py        确定性合成数据（选择偏差 + 迟到退款 + 脏行）
  web/           index.html / styles.css / app.js（状态与控件）/ views.js（结果、图表、对比、数据页）
tests/           unittest：接入、快照、版本、报告生命周期、并发、分析、HTTP API
```

### 主要 API

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/bootstrap` | 方法/规则/观察窗/快照/组合/筛选项 |
| GET | `/api/state` | 批次、拒绝行、快照、版本、报告状态 |
| POST | `/api/reports` | 入队报告（可带 `rule_overrides` / `cohort_overrides`，自动建新版本） |
| GET | `/api/reports/{id}` | 报告（含 payload、事件、运行、陈旧标记） |
| GET | `/api/reports/{id}/evidence` | 依据 JSON + 复现请求体 |
| GET | `/api/reports/{id}/stores.csv` | 门店级 CSV |
| GET | `/api/reports/{id}/methodology.md` | 方法说明 |
| GET | `/api/stores/{store_id}?report_id=` | 门店周度下钻 |
| POST | `/api/compare` | 两版报告输入差异与指标差 |
| POST | `/api/ingest/backfill` | 回补退款并冻结新快照 |
| POST | `/api/rule-versions` · `/api/cohort-versions` | 显式创建版本 |
